# 可执行开发规范

适用对象：本仓库维护者、贡献者与AI。基线为Minecraft 1.21.1 / Java21 / RS2.0.7、common/Fabric/NeoForge三模块，当前0.5.0未发布。注册标识已重写为refinednetwork，旧namespace不迁移。本文是现行规范，历史DESIGN/审计/移植方案仅作溯源。

## 1. 权威与冲突处理

维护者当前明确指令→批准的Issue/决策→本规范与AGENTS→当前源码/测试证据→历史记录。Issue不能暗中取消安全和验证要求；发现冲突先说明具体文件、规则与决策缺口，由维护者决定。源码描述现状不自动决定目标行为；测试失败也不自动证明规范错误。

每次任务记录基线SHA、Git状态和目标Issue。先区分代码已确认、静态推断、已复现、需要产品决策四类证据；推断任务先复现，有证据才修。依赖未满足时不继续下游实现。

## 2. 模块职责

| 位置 | 应做 | 禁止 |
|---|---|---|
| refinednetwork-common/src/main/java | 共用状态、操作、费用、业务菜单、权限调用、设备生命周期 | importing Fabric/NeoForge实现；服务端类静态引用客户端代码 |
| refinednetwork-common/src/main/resources | 共用assets/data、语言、配方、标签、掉落 | 改显示名时同时改注册ID；漏掉调用引用或只改单语言 |
| refinednetwork-common/src/test/java | 费用、算法、状态、序列/缓存差量等可隔离测试 | 空断言、删除回归、把旧测试记录当新运行 |
| fabric | 事件、平台注册/配置、能量事务、菜单打开、Mixin及客户端注册 | 独立复制common业务规则；模拟过程写入缓冲 |
| neoforge | 对应事件/能力/配置与客户端注册 | 平台侧新增与Fabric不一致的免费/越权行为 |
| root build / .github | 依赖、构建、校验、版本与发布契约 | 为修文案升级工具链、悄悄发版或跳过测试 |
| gen_*.py | 已声明的生成范围；源与输出同步 | 未看写入目录先执行全套生成；纹理混入非美术Issue |

新增共用逻辑优先放所属领域包，不强制建立全局服务。只有至少两个真实消费者和明确职责才抽共用代码；不要凭文档创造ContentRegistry等不存在的框架。

## 3. 风格、名称与ID

- Java21，UTF-8，无BOM，文件末尾换行；Java使用空格，默认4空格缩进。120列与700行上限由现有Checkstyle控制；特殊长链接按配置豁免，不修改阈值躲检查。
- 类UpperCamelCase、方法/字段lowerCamelCase、常量UPPER_SNAKE_CASE；包小写。参数和可不变局部使用final，避免通配符导入；import按现有同包/Java/第三方/static分组字母序。
- Checkstyle源为config/checkstyle/checkstyle.xml及其imports/suppressions；IDE配置是辅助。禁止增加抑制、忽略失败、去掉测试来掩盖问题。
- 注册path用lower_snake_case，集中查ContentIds；翻译键查ContentNames/ModIdentifierUtil；ID、显示名、Java包、模块名、JAR名是五类独立决策。
- Java注释解释原因、边界和契约，不写宣传或无证据“永远不会”。本轮不为了旧注释大范围触碰业务Java，另立注释Issue。
- JSON 2空格、保持顺序和占位符；语法用ASCII直引号。中文/英文术语依TEXT_REVIEW，不增加装饰emoji。

## 4. 修改范围与低参数模型工作流

1. **读取**：Issue和依赖、相关模块、相邻实现、对应RS实际源码/API签名、测试与资源引用。限制搜索在项目及明确依赖来源，不扫描用户个人文件。
2. **确认**：写最小目标、允许文件、禁止文件和验收映射；不确定的API/原行为/参数在读后仍不明，记录具体问题并询问。禁止“假设某方法存在”。
3. **复现**：缺陷优先新增能失败的定向回归或记录受控手动步骤。仅静态推断未复现时不得直接宣布缺陷事故。
4. **修改**：只做Issue要求；不顺带全局重命名、升级RS/加载器、改玩法数值、加菜单、清理大量格式。发现别的问题建关联任务，不扩范围。
5. **验证**：先定向再模块再集成，按下表真实执行。失败先定位，禁止放宽断言或跳检查；环境阻断保留命令/错误，任务不标完成。
6. **同步与交付**：同步相关文案/CHANGELOG未发布区/生成源；摘要列事实和未验证；维护者复核后关闭Issue。不得未经当前授权提交/push/发版。

Flash接手每条Issue必须能独立回答：做什么、为什么、在哪里、何时失败、不能做什么、怎么证明成功。跨多个子系统或需产品决策任务先产决策，不给模型“自行合理补全”。

## 5. 操作正确性契约

- 所有真实读写由服务端执行，客户端输入必须复核权限、数量、终端/目标身份、范围/维度和配置。绑定时权限不能代替持续授权。
- 模拟不改库存/能量/限速额度/持久化；EXECUTE记录实际数量，不凭请求量记账。失败必须零副作用或可解释回滚，部分成功有明确定义。
- 费用预检、最终扣除和成功条件同源；网络不足时不要先抽零头再整笔扣电池。实际charge结果必须传到业务层。
- 每个收费动作定义单位；空Optional任务、失败编码、只读预检不当成成功。不能将输入已消耗的中间快照当整次操作前快照。
- ItemStack引用/槽位、网络绑定代次、规则稳定ID和监听生命周期分别考虑；失效会话关闭或只读按批准语义，不用恒true获得权限。
- 离线本地模式严格不访网；若状态变化不支持热迁移，提示重开，不半在线。订单幂等必须有持久化/故障恢复，不止一个UUID。
- 解绑/重绑/拆除清旧引用/监听/缓存；桥环路有界保护不等于多桥库存去重。
- 当前保活不因欠费暂停释放是既有政策，改动需决策和恢复测试；不能取消属于原版forceload或其他模组的加载，也不静默新增无限强载。

## 6. 标识与持久ID

2026-10-30已按维护者决定完成一次硬重写：modId、命名空间、Java包、模块与产物前缀统一为 `refinednetwork`，**不提供旧 `rswirelesscrafting` 存档迁移**。之后不得再出现旧标识，也不得为了让旧世界“看起来能用”而加入未验证的别名映射。

改动任何持久标识（modId、注册path、数据组件字段、NBT键、配置键）仍需单独决策与盘点：平台声明与build、assets/data命名空间、注册单例与持久字段、mixin配置、饰品tag、生成脚本、历史文档例外。历史发行说明保留旧名是正确做法，不要改写成新名。

禁止对全仓直接replace_all后直接发布；不改上游refinedstorage ID；不在维护者个人世界上试迁移；标识变更不与功能修复混在同一提交。若未来再次改名，必须显式说明旧世界不可直接加载，并逐平台验证。

## 7. 测试与验证矩阵

命令在仓库根、JDK21执行；Windows用gradlew.bat，Git Bash可用./gradlew。使用既有镜像需要记录选择，不能下载并运行未知脚本。

| 修改类型 | 最少验证 | 不能推导 |
|---|---|---|
| 纯Markdown/Release | diff --check、链接/事实/历史快照；线上写后读回 | 不等于游戏构建或兼容测试 |
| 语言/元数据描述 | JSON无重复键、键与占位符、生成一致、mod声明ID不变；目标游戏语言加载待测 | 文案不等于修了业务缺陷 |
| 共用纯算法 | ./gradlew :refinednetwork-common:test、相关checkstyle | 纯逻辑通过不等于菜单集成通过 |
| common业务/资源 | 定向回归、./gradlew build、双平台相关游戏场景 | NeoForge通过不等于Fabric通过 |
| 平台能力/Mixin | 双平台build、各平台生产JAR客户端和专服，目标RS版本 | 开发映射成功不等于生产映射安全 |
| 持久ID/组件/票据 | 双平台新世界/备份旧世界、重启/卸载/回滚/故障窗口 | 存档可打开不等于物品完整保留 |
| 发布流水线 | tag/ref/version/body/asset校验、只读或dry-run检查，不建真实Release | CI脚本语法通过不等于发布正确 |

检查命令：`git diff --check`、`./gradlew build`、`./gradlew -I init-mirror.gradle build`（需要时）、`./gradlew :refinednetwork-common:test`。Checkstyle任务名称先用`./gradlew tasks --all`确认，不编造不存在任务。菜单/供能/桥/迁移至少检查成功、无权限、欠费、目标变化/卸载、重开/重启、并发、模拟/执行。

测试世界必须备份/隔离；不自动移动/删除用户mods、存档、配置。测试报告写实际配置和版本、前后库存/能量、命令退出码、日志路径；失败/未执行明确标注。不要在构建产物混存多版时只看文件存在。

## 8. 文档与生成同步

README记录当前可用/开发分支/限制；CHANGELOG仅真实变更放未发布区，不篡改旧日期；RELEASE_NOTES是目标发行草稿，需tag和版本匹配。docs/releases保存历史勘误正文，不修改旧JAR来“修复历史”。

中英资源与gen_lang覆盖子集同时改；生成两次第二次字节不变，非覆盖键保留。其他generator先看写哪些文件，需求外输出保留原样并另立任务。图片内文字和外部网站未更新要说清，不推导为已同步。

开发/AI自用材料Markdown足够，不为封面/字体/转换浪费时间；面向外部的README、Release重视结构、可读性和信息准确，不为了版式制造额外Office。

## 9. 完成标准与汇报

- [ ] 每个具体需求和验收项有实现/证据对应，依赖已完成或正式解除。
- [ ] 差异限定目标文件，不包含无关功能/ID/依赖/生成资产；原用户改动保留。
- [ ] 回归证明修复前后或明确手动结果；所需测试运行并通过，不删测试、不忽略错误。
- [ ] 文案/资源/生成源/未发布变更与行为一致；推断和实际运行分开。
- [ ] 模拟、失败、部分成功、权限撤销、持有/目标变更和迁移适用时均覆盖。
- [ ] 本地与线上状态分别说明：已修改、已提交、已push、已创建Issue、已发版不能混称。
- [ ] 交付修改文件、验证命令与结果、未运行/风险/待确认；维护者复核后才关Issue。

任一阻断未解决时，只报告“部分完成/待验证”。允许调研Issue以有证据的否定结论结束，不为了做修复而编造问题。未来内容方向可扩大，但每项先立项，不能由模型按“做大附属”自行新增大量机器。
