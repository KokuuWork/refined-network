## 模块与入口

| 模块 / 位置 | 责任 | 不应承担 |
|---|---|---|
| `rswirelesscrafting-common` | 共用玩法、菜单数据、终端费用、规则、设备逻辑、资源与纯逻辑测试 | 直接依赖某加载器实现，服务端路径加载客户端类 |
| `rswirelesscrafting-fabric` | 初始化、Fabric事件、配置、能量事务、客户端注册与平台Mixin | 复制一套独立玩法或与NeoForge规则分叉 |
| `rswirelesscrafting-neoforge` | 初始化、NeoForge事件、配置、能力、客户端注册与平台Mixin | 用平台注册代替共用业务校验 |
| `Platform`及平台实现 | 能量、配置、槽位引用和平台能力适配 | 虚构不存在的通用注册器 |
| `ContentIds` / `ContentNames` / 注册单例 | 注册路径、翻译键与公共内容定义 | 擅自变更持久ID以整理名称 |

公共Java根：`com.kokuu.rswirelesscrafting.common`。模块名、包名和modId不同概念；后续改变modId不自动要求同时改包与模块名称。

## 功能链

- `terminal` / `upgrade`：终端共用物品、费用工具、4槽插件；`wirelesscraftinggrid`上下文包装RS网络物品能力与费用。
- `wirelesscraftinggrid`：库存操作、矩阵保存、配方及任务入口；离线本地模式已加入，但入口隔离与重连待验证。
- `patterngrid` / `autocraftermanager` / `virtual`：虚拟RS实体与菜单复用，避免世界内幽灵节点；不要恢复AIR构造，也不要为显示active把虚拟实体注册进网络。
- `monitor` / `notify`：携带监控终端的规则检查、聊天提醒和RS补货；没有自有持久订单或离线托管。
- `link`：绑定解析、配对剪贴板、权限助手、网络挂载及加载引用。接口名称不意味着所有功能已统一使用。
- `bridge`：据点将自身容器挂到远端网，维护两端保活记录、费用与红石暂停；邻接线缆拓扑和冷启动恢复要独立测试。
- `networkbridge`：远端资源代理、复合库存差量缓存、物品 / 能量速率与递归保护；缓存有实现但缺主动更新闭环风险，不是已证实复制。
- `energyreceiver`：绑定供电方→缓冲→相邻本地网；缓冲不同时计入两网。`energymonitor`只读采样趋势。
- `smartsorter`：过滤、定向容器搬运、输入面、余量处理。`configcard`复用RS设置；不搬升级卡。
- `redstonelink`：端点坐标配对，0 / 15采样；输入身份和所有权入口缺口待处理，不主动加载区块。

## 当前行为不等于目标契约

1. 远程费用应统一，但`VirtualTerminalSession`和合成上下文的电池兜底现在不一致。
2. 菜单恒存活是为解决虚拟实体不在世界中的问题，不是长期权限或物品持有校验策略。
3. 离线矩阵保存不是持久化自动合成队列；RS已提交任务由RS机器负责。
4. `require=0`不是任意字段变化的安全保证；公共API优先，非稳定类与Mixin按目标版本核对。
5. 区块保活当前不因欠费 / 红石暂停释放；`chunkLoading=false`只阻止新增，不是管理员清票操作。改变政策必须另立任务。
6. 递归保护不是多桥共享远端库存的去重机制；状态 / 缓存 / 模拟与执行需要一致验证。

## 内容扩展方向

维护者希望发展成内容丰富的大型RS附属。历史“只做无线、不做新机器”等不是永久禁令。允许研究存储管理、自动化生产、网络基础设施、监测控制和实用工具等方向，但每个内容先说明玩家需求、与RS原生 / 已有附属的差异、资源流、费用、权限、性能、加载和失败语义，再拆成独立可验收Issue。

本轮只治理文案、规范和任务，不实现上述新内容、不修改modId。迁移前先确认目标ID与旧世界策略；迁移与功能修复分开提交、验证，避免无法定位回归。
